API keys

Nupta has no server. Your keys are encrypted on this device with a passphrase only you know, and are sent to nobody but the AI provider you chose. What this does and doesn't protect.

Set a passphrase to start storing your own API keys. There is no recovery — if you forget it, the stored keys are gone and you paste them again.

Your keys are locked. Unlock once per browser session to use them.

Model for each feature

Pick a model per feature. Features sharing a model are answered in a single request — keeping everything on Gemini is one free call per checkpoint.

Where your keys go

  • Nowhere near a backend — there isn't one. Nupta is entirely on-device.
  • Encrypted at rest with AES-GCM; the encryption key is derived from your passphrase (PBKDF2-SHA256, 600,000 iterations). On disk there is only ciphertext.
  • Never in a web page. Keys are decrypted only inside the extension's service worker — never in the widget injected into the lecture page.
  • One destination. A key is sent only to its own provider's HTTPS endpoint, to answer your lecture.
  • The honest limit: while the vault is unlocked, the decryption key is held in browser session memory. Someone with access to your unlocked Chrome profile could extract it. Lock the vault, or quit Chrome, to clear it. No in-browser code can defend against malware already running as you.
